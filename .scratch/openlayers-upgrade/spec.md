# OpenLayers ~10.11.0 升级与组件 NEW 标签移除需求设计

Status: resolved

Type: task

Labels: ready-for-agent

## Problem Statement

维护者希望将项目的 OpenLayers 依赖从 `~10.9.0` 升级到
`~10.11.0`，让开发环境、文档应用和组件库使用者采用一致的版本要求，同时保持现有 Angular 组件接口和地图示例可用。

当前根项目开发依赖、文档应用运行依赖和组件库的 `ol` peerDependencies 共用 pnpm
catalog，锁文件与本机安装版本均为 `10.9.0`。安装说明及当前源码兼容矩阵仍要求
`~10.9.0`，仅修改依赖版本会使使用者收到过时的安装指导。

Raster 组件现有的动态 source 增删逻辑直接同步 OpenLayers 内部 layer 和 frame state。OpenLayers
10.11 新增了区分原生 DataTile 数据采样与渲染后 RGBA 采样的逐项状态，而现有同步逻辑没有维护它。嵌套 DataTile 组件会在 Raster 实例创建后加入，存在走错采样分支的实际风险。现有增删测试仅检查不抛错，不能证明数据采样正确。

此次跨越 10.10 和 10.11 两个次版本，还需要明确浏览器要求、上游行为修正及弃用提示，避免使用者将这些差异误认为组件库接口变化。

文档维护者还要求移除全部组件文档的 `NEW` 标签，使组件导航与页面状态展示不再将这些组件标为新增。

## Solution

通过现有 pnpm catalog 将所有直接使用的 `ol` 声明和组件库 peer 要求统一升级为
`~10.11.0`，更新锁文件，并修复 Raster 动态 source 的必要状态同步。

继续保持同一 Raster 实例和现有 Angular 组件接口，通过真实浮点数据读取验证增删 source 后的数值、顺序和生命周期清理。结合现有工作区检查、真实发布 tarball 及浏览器示例验收，保证升级后的依赖能够安装、编译、打包和运行。

同步当前源码安装说明与兼容矩阵，保留历史发布版本的真实要求。接受上游公布的行为修正，需要兼容缺少
`Intl.Segmenter` 的旧浏览器时由宿主应用提供 polyfill。

统一移除组件文档页面元数据中的 `NEW` 状态，重新生成文档后，导航与页面均不再展示该标签。保留
`EXPERIMENTAL` 等其他状态及现有状态标签展示能力。

## User Stories

1. 作为维护者，我希望 OpenLayers 的统一版本声明为 `~10.11.0`，以便项目采用目标次版本。
2. 作为维护者，我希望版本范围允许 10.11.x 补丁更新，以便获得同一次版本内的修复。
3. 作为贡献者，我希望根开发环境和文档应用使用一致的 OpenLayers 版本，以便避免开发与示例运行环境不同。
4. 作为组件库使用者，我希望 `ol` peerDependencies 明确要求
   `~10.11.0`，以便判断应用是否满足支持条件。
5. 作为维护者，我希望继续通过 catalog 集中管理依赖，以便避免多个包重复维护版本声明。
6. 作为贡献者，我希望锁文件与依赖声明一致且冻结安装成功，以便复现经过验收的依赖环境。
7. 作为维护者，我希望锁文件改动只涉及本次升级及必要传递依赖，以便控制升级范围并便于审查。
8. 作为组件库使用者，我希望现有组件、输入、输出和公开方法继续可用，以便无需因本次升级调整 Angular 模板。
9. 作为 Raster 使用者，我希望实例创建后动态加入 DataTile
   source 能正确读取原生数据，以便通过嵌套组件组合数据源。
10. 作为 Raster 使用者，我希望浮点 band 值在采样时保持精度，以便数值不会被错误地转为 RGBA 字节。
11. 作为 Raster 使用者，我希望多个 source 的采样结果保持输入顺序，以便处理逻辑使用正确的数据。
12. 作为 Raster 使用者，我希望删除第一个 source 后剩余 source 的采样仍然正确，以便动态组合不会出现索引错位。
13. 作为 Raster 使用者，我希望 ImageTile
    source 与 Layer 输入沿用上游规定的渲染采样，以便不同输入类型使用正确的数据路径。
14. 作为 Raster 使用者，我希望增删 source 时保持同一个 Raster 实例，以便已有实例引用和事件订阅继续有效。
15. 作为组件库使用者，我希望嵌套 source 组件销毁后从 Raster 中移除，以便后续采样不再包含已移除的数据。
16. 作为组件库使用者，我希望 Raster 组件销毁时清理事件与宿主绑定，以便组件生命周期保持可靠。
17. 作为测试维护者，我希望新增回归测试验证真实采样结果，以便能发现只检查不抛错无法发现的问题。
18. 作为测试维护者，我希望复用现有组件测试和公开实例接口，以便无需新增仅供测试使用的接口。
19. 作为贡献者，我希望现有脚本、组件库和文档测试继续通过，以便升级不会破坏已覆盖的行为。
20. 作为维护者，我希望组件库和文档应用构建通过，以便真实类型与打包兼容问题能够被发现。
21. 作为维护者，我希望正式与 preview 文档构建都通过，以便两种访问路径继续可用。
22. 作为组件库使用者，我希望实际 tarball 中的 peer 要求正确，以便安装时获得可执行的兼容约束。
23. 作为组件库使用者，我希望全部 secondary entry point 及导出文件完整，以便原有功能入口继续可用。
24. 作为文档读者，我希望根目录和库安装说明都要求正确的 OpenLayers 版本，以便按照说明准备依赖。
25. 作为文档读者，我希望当前源码兼容矩阵与历史发布版本明确区分，以便不会用新要求误读旧版本。
26. 作为文档读者，我希望固定版本的 OpenLayers API 链接与升级目标一致，以便查看对应版本的接口。

28. 作为组件库使用者，我希望了解 GeoJSON 空坐标、Canvas 插值和 WMTS 默认行为的变化，以便识别上游升级带来的差异。

31. 作为审查者，我希望看到安装、测试、构建、打包与浏览器检查的记录及截图，以便判断升级是否满足验收标准。
32. 作为维护者，我希望需求、确认决策和实施验收能在本地 issue

33. 作为发布维护者，我希望本次保持工作区包版本并由后续流程发版，以便依赖升级与正式发布分别管理。
34. 作为文档维护者，我希望移除所有组件文档的 `NEW` 状态元数据，以便统一清理组件的新增标记。
35. 作为文档读者，我希望组件导航与页面都不再展示 `NEW` 标签，以便两处状态信息一致。
36. 作为文档读者，我希望 `EXPERIMENTAL` 等其他状态继续显示，以便仍能判断组件的实验状态。
37. 作为文档维护者，我希望正式与 preview 构建都包含标签清理结果，以便生成内容不会保留过时的 `NEW`
    标记。

## Implementation Decisions

- 根开发依赖、文档应用运行依赖和组件库的 `ol` peerDependencies 统一使用
  `~10.11.0`。使用者需要 OpenLayers 10.11.x；本次不声明兼容 10.9.x 或 10.10.x。
- 继续使用现有共享 catalog 和各包的 `catalog:`
  引用。更新锁文件，实际补丁版本及必要传递依赖由锁文件固定；不跨入10.12，不进行无关依赖刷新。
- 使用项目指定的 pnpm 10.34.5 和现有 Node
  24 环境。保持现有 Angular、Nx、NgDoc、TypeScript 及测试工具链；三个 workspace 包版本均保持
  `22.0.1`。
- 组件库继续提供现有组件、输入、输出和公开方法；不主动为 OpenLayers 新选项增加 Angular 封装。本次兼容修复限定为升级直接影响的已有功能。
- Raster 动态 source 更新继续在原实例上完成，不通过重建实例改变 `getInstance()`
  返回对象的身份或已有订阅关系。
- 在同一次 source 更新中同步 `layers_`、`frameState_.layerStatesArray` 和
  `sampleArrayData_`。layer 状态与实例使用同一批创建的 layer，避免重复创建造成对象不一致。
- 采样标记按原输入顺序计算并跟随增删同步：裸 DataTile source 且不是 ImageTile
  source 时使用原生数据采样；ImageTile
  source、其他受支持 source 和 Layer 输入使用渲染采样。Layer 即使包含 DataTile
  source，也遵循上游的渲染采样规则。
- 保持嵌套 source 注册、销毁时移除以及 Raster 的宿主绑定和事件清理语义。兼容处理复用现有生命周期入口。
- 接受上游公布的行为修正，不模拟 10.9 的旧语义。迁移说明涵盖 GeoJSON 空坐标解析为 null、Canvas 颜色插值改为 sRGB，以及 WMTS
  capabilities 的 extent、wrapX 和 tile matrix limits 变化。
- 沿用上游对 `Intl.Segmenter`
  的要求。需要兼容缺少该能力的旧浏览器时，由宿主应用提供polyfill；组件库不新增对应运行时依赖。
- 保留现有 BingMaps 组件及接口，注明上游弃用状态，不在本次迁移到其他地图服务。
- 同步根目录与库 README、入门指南和 Introduction 中当前源码的兼容要求；更新 Snap 文档中的固定版本 API 链接。历史发布兼容矩阵、历史升级验收记录以及测试中的历史版本样例保留原值。
- 文档继续区分当前源码与已发布包，并指导使用者查看所选发布版本的 peerDependencies。
- 组件文档清理覆盖全部组件分类及组件目录中的相关文档页面，移除 NgDoc 页面元数据中的
  `@status:info NEW` 及其他同义 `NEW`
  状态声明，从来源消除标签；不能仅通过 CSS、侧栏过滤或修改生成产物隐藏。
- 仅移除 `NEW` 状态，保留 `EXPERIMENTAL`
  等其他状态、组件页面内容和通用状态标签渲染能力。标签清理纳入文档同步任务，并重新生成正式与 preview 文档。
- 实施任务按依赖及兼容修复、文档同步、集成验收拆分；集成验收依赖前两项完成。实施过程中记录结果、必要修复和截图。

## Testing Decisions

- 好的测试验证使用者可观察的采样结果、公开接口、生命周期、安装结果和真实产物，不复述版本声明或私有字段的赋值过程。
- 优先沿用现有测试边界：Raster 组件及 `getInstance()`
  返回的公开 OpenLayers 接口、现有工作区检查、真实发布 tarball 和文档示例。无需新增测试专用 API。
- Raster 回归沿用 colocated Vitest、Analog
  Angular 集成和 jsdom，复用现有 source 增删、组件宿主绑定及销毁测试。现有仅断言不抛错的增删用例不足以作为升级验收。
- 使用真实 DataTile loader 和最小 tile grid，通过 `getImage()` 驱动加载，再由 `getData()`
  验证浮点 band 数据，例如保留 `42.5` 和 `7.25`。优先使用
  `threads: 0`、不设置 operation 的采样场景，避免依赖 Worker 或输出 canvas；不 mock 掉待验证的采样逻辑。
- 覆盖 Raster 创建后首次动态添加、添加多个 source 后的采样顺序、删除首项后的数值与顺序、嵌套组件注册及销毁移除、原实例身份保持。验证清理事件订阅与宿主绑定的既有生命周期行为。
- 验证 ImageTile
  source 与 Layer 输入继续遵循渲染采样语义，避免兼容修复将所有 DataTile 派生输入都误判为原生数组。
- 新回归应能发现未同步采样状态时的错误；不能以仅检查私有标记或不抛错代替数值断言。
- 更新锁文件后，`pnpm install --frozen-lockfile` 必须成功。
- `pnpm test` 必须通过，覆盖现有脚本、组件库和文档应用测试；`pnpm lint` 与 `pnpm format:check`
  必须通过。
- `pnpm build`、`pnpm build:docs` 和 `pnpm build:docs-preview` 必须通过。
- 使用项目指定的 pnpm 对真实库构建产物打包，检查 tarball 的 `peerDependencies.ol` 为
  `~10.11.0`，没有未展开的 catalog 引用，全部 secondary entry point 及其导出目标完整。
- 对生产文档产物进行浏览器冒烟检查：OSM 地图基本交互、向量图层旋转、矢量瓦片和 GeoTIFF/WebGL 示例。记录渲染结果、控制台错误和截图；jsdom 中的 fake 或 mock 不能证明真实 Worker/WebGL 渲染兼容。
- 盘点全部组件文档的状态声明，确认 `NEW` 状态已清空；正式与 preview 文档的生成元数据均不再包含组件
  `NEW` 状态，避免只检查少数页面而遗漏其他分类。
- 浏览器检查组件侧栏与页面状态展示均没有 `NEW` 标签，现有 `EXPERIMENTAL`
  标签仍正常显示。复用侧栏对空状态及其他状态的现有测试，不新增仅复述注释删除的逐文件单元测试。
- 验收记录应区分升级缺陷与外部服务、网络或授权限制；受限检查不能记为通过，也不因此扩大升级范围。

## Out of Scope

- 封装 OpenLayers 新功能、增加组件输入或输出、无关重构。
- 维护或验证 OpenLayers 10.9.x、10.10.x 的组件库 peer 兼容范围。
- 在组件库内置 `Intl.Segmenter` polyfill，或模拟上游已修正的旧行为。
- 移除 BingMaps 组件、切换地图服务或调整外部服务授权配置。
- 升级其他工具链、修改文档引擎、切换测试运行方式或新增测试专用接口。
- 改写历史发布版本的兼容信息、历史验收记录或版本样例。
- 移除 `EXPERIMENTAL` 等其他状态标签，或改造通用状态标签展示逻辑。
- 修改 workspace 包版本、执行发版、发布 npm 包或部署文档站点。
- 为普通依赖升级新增通用技术术语或 ADR。
