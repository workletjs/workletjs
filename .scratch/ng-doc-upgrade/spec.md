# NgDoc ~22.1.0 升级与新引擎迁移需求设计

Status: open

Type: task

Labels: ready-for-agent

## Problem Statement

文档维护者希望将项目的 NgDoc 从 `22.0.0-beta.2` 升级到
`~22.1.0`，严格按照官方升级及新引擎迁移文档实施，使文档开发、构建和部署继续可靠运行。

当前文档应用使用旧 NgDoc builder，直接依赖 Vite
7；正式站点、preview 和版本站点通过构建参数设置部署子路径。现有自定义首页、侧栏、状态徽标和路由也依赖 NgDoc 的生成内容与 UI。只修改依赖版本，无法保证新引擎、测试工具链和部署接口兼容。

现有文档单元测试大量 mock
NgDoc 并替换组件模板，不能证明真实文档、搜索、组件 API 和地图示例在新引擎下正常工作。PR
CI 目前仅构建组件库，文档构建问题可能直到部署阶段才被发现。

## Solution

将五个直接使用的 NgDoc 包统一升级至
`~22.1.0`，执行官方版本迁移，再通过官方 schematic 将 docs 的默认构建和开发服务迁至 Vite 新引擎。

文档构建使用 Vite 8.3 及以上的兼容版本，测试继续使用现有 Vite 7、Vitest 4.0.9 和 Analog
2.8.0，通过依赖上下文隔离避免混用编译配置。保留开发、正式和 preview 构建的现有命令入口，以环境变量传递部署子路径。

保留项目自定义首页、侧栏、状态徽标和现有 URL，同时接受 NgDoc 新版默认主题、API 展示、示例工具栏和快捷键。保留官方旧引擎目标、隔离配置及回退快照，并将文档生产构建加入 PR
CI，以实际构建、浏览器行为和回退演练验收。

## User Stories

1. 作为文档维护者，我希望五个 NgDoc 包统一使用 `~22.1.0`，以便避免运行时与生成器版本不一致。
2. 作为文档维护者，我希望升级严格遵循官方文档，以便迁移过程可审查并具备官方支持的行为。
3. 作为维护者，我希望版本迁移以当前 beta 版本为明确基线，以便不遗漏正式版本新增的迁移。
4. 作为维护者，我希望同时检查 22.0 到 22.1 的增量变化，以便不遗漏目标版本新增的兼容要求。
5. 作为贡献者，我希望依赖继续由 pnpm catalog 集中管理，以便多个工作区包使用一致的版本声明。
6. 作为贡献者，我希望锁文件与声明一致且冻结安装成功，以便复现经过验收的环境。
7. 作为文档维护者，我希望 docs 默认使用新引擎，以便获得持续缓存、增量重建和诊断信息。
8. 作为维护者，我希望正式迁移前能查看 dry-run 和迁移报告，以便确认改动范围及手动处理项。
9. 作为文档维护者，我希望保留旧引擎构建与服务目标，以便出现问题时能够使用旧引擎。
10. 作为维护者，我希望新旧引擎使用各自的生成目录，以便交替运行时不会覆盖彼此的产物。
11. 作为维护者，我希望保留官方回退快照并验证回退命令，以便在需要时恢复旧引擎。
12. 作为维护者，我希望明确引擎回退与完整升级回退的区别，以便选择正确的恢复方式。
13. 作为文档维护者，我希望新引擎完整发现指南和组件文档，以便迁移不会遗漏页面或分类。
14. 作为文档维护者，我希望扫描范围仅包含项目文档来源，以便避免读取依赖、临时目录或其他工作区副本。
15. 作为测试维护者，我希望只为文档构建引入 Vite 8，以便控制本次升级范围。
16. 作为测试维护者，我希望保留 Vitest 4.0.9 和库测试的 Vite 7，以便继续使用已经验收的测试工具链。
17. 作为测试维护者，我希望文档测试使用兼容 Vite
    7 的 Angular 插件实例，以便避免构建与测试混用编译配置。
18. 作为测试维护者，我希望构建配置与测试配置分别被正确加载，以便测试发现和运行保持可靠。
19. 作为贡献者，我希望 `pnpm start` 继续启动文档应用，以便沿用现有开发入口。
20. 作为贡献者，我希望正式和 preview 构建快捷命令继续可用，以便无需改变常用工作流。
21. 作为部署维护者，我希望根站、preview 和版本站点继续支持各自的子路径，以便现有部署地址保持可用。
22. 作为部署维护者，我希望部署子路径通过明确的环境变量传递，以便适配新 builder 的配置接口。
23. 作为部署维护者，我希望不同子路径构建不会复用错误产物，以便页面和资源始终指向正确位置。
24. 作为文档使用者，我希望刷新深层链接后仍能打开页面，以便已有链接和书签继续有效。
25. 作为文档使用者，我希望首页、自定义侧栏和分类导航继续可用，以便沿用熟悉的访问方式。
26. 作为文档使用者，我希望 NEW 和 EXPERIMENTAL 徽标继续显示，以便了解组件状态。
27. 作为文档使用者，我希望页面顺序、默认跳转和锚点保持，以便迁移后仍能找到原有内容。
28. 作为文档使用者，我希望新版主题和移动布局正常工作，以便在不同设备及主题下阅读文档。
29. 作为文档使用者，我希望搜索能找到指南和组件页面，以便快速定位需要的说明。
30. 作为文档使用者，我希望示例预览及源码面板正常工作，以便理解组件的实际用法。
31. 作为组件库使用者，我希望生成的 API 正确展示输入、输出、模型和注释，以便准确理解公开接口。
32. 作为组件库使用者，我希望内部成员不会被误展示，以便区分受支持的公开 API。
33. 作为文档使用者，我希望地图、绘图表单和 WebGL 示例正常运行，以便体验组件功能。
34. 作为文档使用者，我希望代码块、复制功能和源码中的反斜线保持正确，以便复制后能够使用。
35. 作为文档维护者，我希望编辑文档或示例后开发服务能正确更新，以便新引擎支持日常开发。
36. 作为 CI 维护者，我希望 PR 阶段执行文档生产构建，以便在部署前发现文档编译问题。
37. 作为维护者，我希望所有部署路径和回退行为都有真实验收记录，以便评估迁移是否完成。
38. 作为审查者，我希望看到迁移报告、手动调整和截图，以便理解改动及已接受的差异。
39. 作为组件库使用者，我希望本次升级保持组件库版本和公开 API，以便文档工具升级不改变库的使用契约。

## Implementation Decisions

### 依赖与官方版本迁移

- `@ng-doc/app`、`@ng-doc/builder`、`@ng-doc/core`、`@ng-doc/keywords-loaders`、`@ng-doc/ui-kit`
  的 catalog 声明统一为 `~22.1.0`，实际解析为同一版本；保留各工作区包的 catalog 引用并更新锁文件。
- 保留现有 Angular 22.2.x、Nx 23.3.0、TypeScript 6.0.3、Node 24 约束、pnpm 10.34.5 和 Analog
  2.8.0；三个工作区包的版本保持 `22.0.1`。
- 以 `22.0.0-beta.2` 为明确基线，使用 Nx 的 `--from`
  收集官方版本迁移，审核后执行。五个包的 catalog 归一化单独处理，不能假定 Nx 会更新全部子项目声明。
- 版本迁移执行时通过 `NODE_PATH` 补充文档应用的依赖解析路径，不为解析问题将 builder 永久加入根依赖。
- 检查官方 22.0 升级说明及 22.0 到 22.1 的增量说明；只修改项目实际使用的受影响接口，包括 signal
  API、移除接口、自定义 CSS、Shiki 字体样式和示例源码转义。
- 保留 Angular keyword loader 和项目已有 NgDoc 配置能力；根工作区与文档应用继续解析同一个
  `@ng-doc/app` 实例。

### 新引擎与测试隔离

- docs 的默认 `build` 和 `serve` 使用官方 `vite-application`、`vite-dev-server` 执行器；保留
  `pnpm start`、`pnpm build:docs` 和 `pnpm build:docs-preview` 入口。
- 在干净提交边界使用文档应用安装的官方 schematic
  collection，显式选择 docs 项目，先 dry-run 再正式迁移，并跳过自动安装以便由 pnpm 统一管理依赖。
- 保留官方迁移器生成的独立 Vite 配置、`build-legacy`、`serve-legacy`、旧引擎配套配置及回退快照；逐项审核报告中的迁移、丢弃和手动处理项。
- docs 的直接 Vite 声明使用 `^8.3.0`；testing catalog 的 Vite 7 和 Vitest
  4.0.9 保持。根目录显式提供 Vite 7 与 Analog
  2.8.0，通过一个仅转导出 Angular 插件工厂的共享测试模块供文档测试使用。
- 文档测试采用 `.mts` 格式的独立 ESM Vitest 配置，从 `vitest/config`
  获取配置入口并使用共享测试插件；原测试选项继续保留。NgDoc 构建配置保持独立，不能被 Nx 或根 Vitest 当作测试项目加载。
- 新 builder 必须在自身依赖上下文解析到 Vite
  8.3+；共享 Angular 测试插件和 Vitest 内部必须解析到 Vite 7。保留 Zone 测试初始化方式。
- 保留旧引擎共享配置的字符串扫描路径；新引擎使用独立 NgDoc 配置，继承共享设置，并用路径数组限定指南与组件库两个文档来源。
- 通过 Vite 插件的 `generator.configFile`
  指定新引擎专属 NgDoc 配置。针对发布包中扫描路径类型声明与运行时能力的差异，使用本地配置类型扩展，不修改第三方包或增加强制类型转换。
- 新旧引擎各自拥有生成目录；官方回退恢复旧目标后仍能读取兼容的共享配置。

### 应用与部署契约

- 保留现有指南、组件分类及页面 URL、默认跳转、锚点、文档关键字、分类顺序和状态元数据；保留自定义首页、侧栏、徽标和图标。
- 接受 NgDoc 官方新版默认主题、API 展示、示例工具栏和快捷键，不逐像素复刻旧 UI；修复迁移导致的失效选择器、布局和交互问题，使自定义响应式行为与新断点兼容。
- 使用 `DOCS_BASE_HREF`
  环境变量传递部署子路径，默认根路径。preview 快捷命令提供 preview 子路径，版本工作流提供相应版本子路径；替换新 builder 不支持的
  `--base-href` 参数并更新贡献说明。
- 保留现有 browser 输出目录和 GitHub Pages SPA
  fallback；HTML、脚本、样式、图标、搜索数据及示例源码请求均应使用当前部署子路径。
- docs 构建保持 Nx 任务缓存关闭，防止环境变量变化导致不同部署路径误用构建产物；NgDoc 新引擎自身的内容缓存使用官方默认行为。
- 接受 Vite 新引擎不执行 Angular
  budgets，将差异记入报告；旧引擎目标保留原预算配置，本次不另建体积门禁。

### CI 与回退记录

- PR Checks 增加 docs 生产构建，沿用现有 Node 和 pnpm 环境；部署工作流适配环境变量接口。
- 更新现有部署工作流回归测试，将其加入根脚本测试入口，使 `pnpm test` 实际执行这些检查。
- 保留官方原始状态与备份，不篡改回退快照来强制恢复后续手动调整。迁移报告记录这些调整以及官方引擎回退覆盖范围。
- 官方 `--revert` 用于恢复引擎配置，Git 用于完整撤销依赖、部署和应用改动；二者均应有清晰的使用说明。

## Testing Decisions

- 验收层级沿用此前讨论的工作区命令、真实文档产物、浏览器集成及回退演练；本次文档整理不重新采访或引入新的测试接口。
- 主要验收面是构建并实际运行的文档站点。好的测试验证页面、资源、导航、搜索、API 和示例的外部行为，不依赖生成器内部类、缓存文件布局或源码文本快照。
- 优先复用现有 Vitest、Analog 和 jsdom 单元测试、Node 内置依赖解析测试、部署工作流测试以及前次升级的产物与浏览器冒烟检查。依赖解析和部署配置检查是站点验收的辅助检查，不能替代真实运行验证。
- 冻结安装必须成功；五个 NgDoc 包解析同一目标版本，根与 docs 的 `@ng-doc/app`
  保持单实例。扩展现有依赖解析测试，检查新 builder、共享测试插件及 Vitest 内部实际使用的 Vite 版本上下文。
- `pnpm test`、`pnpm lint`、`pnpm format:check`、组件库构建、docs 正式构建和 preview 构建必须通过。公共行为确实需要适配时，更新对应 colocated 测试，不为普通版本声明增加复述性测试。
- 按根路径、preview 子路径及一个版本子路径依次构建，检查实际 HTML 的 base、输出文件和资源请求路径；浏览器刷新深层路由后，页面及资源应恢复正常。
- 文档内容基线为 87 页、8 个分类、105 个注册示例和 83 处组件 API 渲染。核对页面与示例完整性、分类顺序、状态徽标、默认跳转和锚点；数量一致还需结合代表性页面真实渲染检查。
- 自定义侧栏检查分类折叠、路由激活及 NEW、EXPERIMENTAL 徽标；搜索检查指南、Map 和 Draw；主题与布局检查桌面、移动端、自定义图标和新示例工具栏。
- 组件 API 检查输入、输出、模型及其 change 输出、公开类型与注释，确认内部成员没有误展示。指南检查代码分组、名称、图标、高亮行及复制；示例源码应保留真实反斜线。
- 地图集成检查 OSM 地图渲染和缩放、Draw 的 Material 表单、WebGL
  canvas 初始化、示例预览及源码面板；记录浏览器错误和资源加载失败，区分既有外部服务限制与本次回归。
- 开发服务验证文档及示例编辑后的页面更新。冷、暖构建均应产生可用且一致的文档；内容修改后缓存不能返回旧内容，不设额外性能基准。
- 旧引擎构建和开发服务必须可运行，新旧引擎交替运行不产生输出所有权冲突。在临时副本执行官方
  `--revert`，验证旧目标恢复后可以成功构建，不要求字节级恢复整次升级。
- PR CI 必须实际执行新引擎 docs 生产构建；验收记录保存命令、结果、迁移报告及代表性截图。

## Out of Scope

- 升级 Angular、Nx、TypeScript、Node、pnpm 或整个测试栈的版本。
- 升级 Vitest、UI 和 coverage 配套版本，或将库测试统一迁至 Vite 8。
- 新组件功能、组件库公开 API 调整、组件库版本变更或无关重构。
- 切换 zoneless、新增 SSR、服务端动态渲染或新的部署平台。
- 用默认侧栏替换项目自定义侧栏，或逐像素还原旧版 NgDoc 外观。
- 新增 Angular budgets 的 Vite 等效体积门禁、第三方依赖补丁或兼容性强制 override。
- 新建端到端测试框架、性能基准体系或为本次工具升级引入通用技术术语和 ADR。
- 发布 npm 包、部署站点或把保存需求文档视为升级已经实施。
